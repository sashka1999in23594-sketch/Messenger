# Архитектура Sunnet

## Общая схема

```
┌───────────────────────── Браузер / PWA ─────────────────────────┐
│  React 19 · react-router · TanStack Query (серверное состояние) │
│  Zustand (UI, настройки, реалтайм) · Web Crypto (E2E)            │
└──────────────┬──────────────────────────────┬───────────────────┘
               │ HTTPS REST /api/v1           │ WebSocket /api/v1/ws
┌──────────────▼──────────────────────────────▼───────────────────┐
│ Fastify 5                                                        │
│  периметр: helmet/CSP · rate limit · CSRF · сеанс из cookie      │
│  modules/*: routes (валидация zod) → service (бизнес-логика)     │
│  policy: единая точка авторизации (приватность, блокировки)      │
│  RealtimeHub: сокеты в памяти процесса                           │
└──────────────┬──────────────────────────────┬───────────────────┘
               │ node:sqlite (WAL, FTS5)      │ файлы на диске
            omni.db                        uploads/YYYY/MM/<id>.<ext>
```

## Принципы

1. **Один контракт на клиент и сервер.** `packages/shared` содержит zod-схемы входных данных, типы ответов (DTO), протокол WebSocket и лимиты. Сервер валидирует ими каждый запрос, клиент — формы. Изменили схему — TypeScript покажет все места, которые нужно поправить.
2. **Composition root.** Все сервисы создаются в `apps/server/src/context.ts` и получают зависимости через конструктор. Модули не создают друг друга сами — их легко тестировать и заменять (например, хранилище медиа на S3).
3. **Авторизация в одном месте.** `modules/policy` решает «можно ли X сделать Y»: видеть профиль, писать, комментировать, видеть «в сети», права участника компании или сообщества (`spacePermissions`) и доступ к их чатам (`canSeeSpaceRoom`). SQL-фильтр видимости ленты (`Policy.visiblePostsSql`) общий для всех лент — проверку нельзя «забыть» в новом эндпоинте.
4. **Единая модель контента.** Заметки, фото, видео и Reels — это одна таблица `posts` с полем `kind`. Лайки, комментарии, репосты, закладки, история, рекомендации и поиск работают одинаково для всех форматов. Новый формат (аудио, эфиры) добавляется без переделки остальных модулей.
5. **Навигация как данные.** `apps/web/src/app/navigation.ts` — реестр всех разделов. Из него строятся рельс, дерево, хлебные крошки, палитра Ctrl+K и мобильная шторка. Тест `navigation.test.ts` гарантирует, что в навигации нет тупиков: каждый пункт ведёт на настоящий маршрут.
6. **Чаты — единый механизм.** Каналы, группы внутри сообществ и чаты компаний — это те же чаты (`modules/chats`): переписка, реакции, голосовые, звонки и модерация работают везде одинаково. Пространства (`modules/spaces`) отвечают только за состав и права.

## Сервер (`apps/server`)

| Модуль | Ответственность |
| --- | --- |
| `auth` | вход по шагам (почта/телефон → код → пароль → TOTP), вход по QR-коду, регистрация по слайдам с подтверждением почты, сброс пароля двумя кодами, подсказка к паролю, сеансы, журнал безопасности, удаление аккаунта |
| `system` | служебный пользователь и чат «Sunnet» у каждого (коды входа, уведомления о входе и сбросе пароля), поздравления с днём рождения (`birthdays.ts`) |
| `mail` | отправка писем (Gmail через Apps Script, Brevo/Resend по HTTPS, SMTP, тестовый ящик в разработке), HTML-шаблоны |
| `users` | профили, подписки и заявки, блокировки, скрытие, настройки приватности и уведомлений |
| `policy` | централизованная авторизация |
| `chats` | личные, группы (открытые и закрытые), каналы (комментарии к постам, просмотры, блокировки), секретные, «Избранное»; сообщения с монотонным `seq`, реакции, пересылка, закрепы, прочтение, таймеры самоуничтожения; голосовые, кружки, опросы, упоминания, медленный режим, автоудаление; свои папки (`folders`), пригласительные ссылки (`invites`), отложенные сообщения (`scheduled`), поиск по сообщениям (FTS5) |
| `calls` | звонки 1:1: состояние в БД (вызов → разговор → завершён/пропущен), сигнализация WebRTC через WebSocket только к принявшему сеансу, таймаут вызова, сообщение о звонке в чате |
| `keys` | каталог публичных ключей устройств (E2E) |
| `posts` | публикации всех видов, ленты и ранжирование, комментарии, лайки и «кто оценил», закладки, история, плейлисты, хэштеги, студия, закреп в профиле, уведомления подписчикам с «колокольчиком» |
| `social` | черновики и отложенные публикации, списки авторов, коллекции закладок, скрытые слова (фильтр лент через FTS5) |
| `media` | загрузка (проверка типа по содержимому, лимиты), подписанные ссылки, раздача с Range |
| `stories` | истории (аудитория «все»/«близкие друзья»), реакции, просмотры, архив, «Актуальное» |
| `spaces` | компании и сообщества: роли с правами (битовая маска), категории, чаты с доступом по ролям, приглашения через уведомления, ссылки-приглашения; состав чатов пересчитывается из ролей (`sync`) |
| `stats` | дневные счётчики (`stat_daily`): подписки и отписки, просмотры профиля и постов каналов; ряды строятся назад от текущего значения |
| `notifications`, `search`, `reports` | соответствующие функции |
| `realtime` | WebSocket-хаб, присутствие, «печатает…/записывает…», доставка сигналов звонка в конкретный сеанс |

**Данные.** SQLite через встроенный `node:sqlite`: WAL, внешние ключи, FTS5 для поиска. Идентификаторы — ULID (сортируются по времени, не угадываются). Время — миллисекунды UTC. Миграции — в `db/migrations.ts`, применяются при старте; опубликованные миграции не редактируются, только добавляются новые. Весь SQL параметризован; обёртка `Db` отбрасывает лишние параметры и требует отсутствующие.

**Внешнее хранилище.** Для хостингов с временным диском (бесплатный Render) диск сервера работает как кэш, а данные живут в S3-совместимом хранилище (`lib/s3.ts` — свой клиент с подписью AWS V4, без SDK; B2, R2, Yandex, AWS, MinIO). `db/backup.ts`: при старте, если файла базы нет, он скачивается из `db/latest.db.gz` (ошибка доступа останавливает запуск — иначе пустая база затёрла бы копию); раз в `BACKUP_INTERVAL_SEC` при изменениях (`total_changes()`) снимок `VACUUM INTO` сжимается и отправляется, плюс дневная копия по дню недели и почасовая чистка прежних версий (B2 хранит каждую перезапись). При остановке сервис досылает файлы и последнюю копию. Медиа: после загрузки файл копируется в `media/<storage_key>` (`media.remote_at`), неудачные отправки досылает фоновая задача, а на чистом диске файл скачивается при первом обращении (параллельные запросы ждут одно скачивание). У B2 бесплатно 2 500 скачиваний в день — каждый файл скачивается один раз за время жизни сервера.

**Доставка сообщений.** Сообщение сохраняется в транзакции, получая следующий `seq` чата, затем рассылается участникам через `RealtimeHub`. Отправка идемпотентна: повтор с тем же `clientId` (плохая мобильная сеть) вернёт уже созданное сообщение. После переподключения клиент перезапрашивает список чатов и открытую переписку.

**Миграции.** `001_init` — базовая схема; `002_email` — почта, коды и знакомство; `003_messenger` — голосовые, опросы, звонки, папки, приглашения, отложенные сообщения, поиск по сообщениям; `004_social` — аудитория и реакции историй, «Близкие друзья», «Актуальное», статус/ссылки/закреп профиля, черновики, списки, коллекции, скрытые слова, «колокольчик»; `005_phone` — номер телефона; `006_channels` — комментарии, просмотры, блокировки, дневная статистика; `007_spaces` — компании и сообщества; `008_live` — прямые эфиры, чат эфиров и премьер, напоминания о премьерах; `009_storage` — отметка о копии файла во внешнем хранилище; `010_auth_flow` — незавершённые входы и регистрации (`auth_flows`), журнал отправок кодов для лимитов (`code_sends`), входы по QR (`qr_logins`), дата рождения, пол, подсказка к паролю и служебный пользователь.

**Вход по шагам.** Каждый вход и регистрация — запись в `auth_flows`: клиент держит случайный токен, в базе лежит только его SHA-256, коды — HMAC с `APP_SECRET`. Шаг (`code` → `password` → `totp`, у сброса — `reset_codes` → `reset_password`) хранит сервер, поэтому перескочить шаг нельзя; токен живёт 30 минут, на код — 5 попыток. Лимиты считаются по `code_sends`: 2 кода входа за 30 минут на аккаунт (дальше — «Отправить только в чат Sunnet», 5 за 30 минут), повтор — один раз и не раньше чем через 30 секунд, сброс пароля — 4 раза в час, регистрация — 2 кода за 30 минут на адрес. Код входа отправляется в письмо и в чат Sunnet с системой, браузером и IP; для сброса нужны оба кода, если у человека есть активный сеанс, иначе только код из письма. Вход по QR: новое устройство получает токен (он в QR-ссылке) и отдельный секрет для опроса; устройство, где человек уже вошёл, показывает, кто просит войти, и разрешает или отклоняет; после разрешения новое устройство переходит к паролю. Сброс пароля завершает все сеансы. Старые `/auth/login` и `/auth/register` (одним запросом) работают только вне production — для тестов и разработки.

**Чат Sunnet.** Это обычный личный чат со служебным пользователем `SYSTEM_USER_ID` (`users.is_system = 1`), создаётся при входе. `chats.service` не даёт в него писать, удалять его, выходить из него и пересылать в него; служебного пользователя нельзя заблокировать. Поздравления с днём рождения — фоновая задача раз в час, после 9:00 по Москве: письмо, сообщение в чат Sunnet и уведомление подписчикам и собеседникам (`birthday_greeted_year` не даёт поздравить дважды; родившихся 29 февраля в невисокосный год поздравляем 28-го).

**Фоновые задачи** (`jobs.ts`): удаление сообщений с истёкшим таймером, отправка отложенных сообщений (каждые 10 с) и публикация отложенных постов (каждые 30 с), очистка сеансов, удалённых историй, кодов из писем и незавершённых входов, `PRAGMA optimize`.

## Клиент (`apps/web`)

- `app/` — оболочка (`layout/`), реестр навигации, маршруты (каждый модуль — отдельный чанк), сессия, обработка событий реального времени.
- `features/*` — модули разделов: `chats` (и каналы), `calls` (экран звонка и история), `spaces` (компании и сообщества), `stats` (графики на SVG), `desktop` («Пространство»), `stories`, `feed` (главная), `posts`, `social`, `video`, `shorts` (Reels), `explore` (поиск), `notifications`, `profile`, `settings`, `auth` (вход, регистрация, «Скачать», подтверждение QR; фон на компьютере — небо с солнцем и бликами объектива на чистом CSS, `auth/Sky.tsx`), `help` (сайт помощи по адресу `/help`). Модули используют друг друга только через публичные компоненты (полоса историй, карточка поста, окна выбора).
- `shared/` — API-клиент (CSRF, ошибки, загрузка с прогрессом), UI-кит, хуки, сторы, E2E-криптография, подготовка медиа (сжатие фото с удалением EXIF, обложки видео).

**Состояние.** Серверные данные — TanStack Query; оптимистичные обновления (лайки, отправка сообщений, реакции на истории) сразу отражаются во всех закэшированных местах и откатываются при ошибке. Настройки устройства (тема, палитра, шрифт, скругления, обои, звуки, «Не беспокоить», стартовая страница, код-пароль) — Zustand с `persist`; визуальные применяются атрибутами `data-*` на `<html>`, которые переопределяют CSS-переменные из `styles/tokens.css`.

**«Пространство».** Режим рабочего стола рендерится вне общего `BrowserRouter`: у каждого окна свой `MemoryRouter` и те же маршруты (`AppRoutes` с другой оболочкой), поэтому окна независимы и сохраняют свою историю. Поле — CSS-трансформация `translate + scale`; развёрнутое окно получает обратный масштаб и остаётся чётким. Окна и вид хранятся в `localStorage`.

**Звонки.** `shared/calls/engine.ts` — конечный автомат звонка (исходящий → входящий → соединение → разговор → завершён) поверх `RTCPeerConnection`; экран звонка смонтирован в оболочке и живёт поверх любых страниц. Адреса TURN выдаёт сервер (`GET /calls/config`): временные учётные данные Cloudflare Realtime, ссылка Metered или статический список из окружения — секреты провайдера остаются на сервере.

**Прямые эфиры.** Без медиасервера: браузер ведущего держит отдельное `RTCPeerConnection` на каждого зрителя (до 50), сервер только пересылает сигналы `live.signal` между сессией ведущего и ключом зрителя и следит за составом (`modules/live`). Битрейт снижается с ростом аудитории; эфир параллельно пишется `MediaRecorder` и после завершения публикуется как обычное видео. Если ведущий пропал, эфир ждёт 20 секунд и завершается. Для аудиторий больше 50 следующий шаг — SFU (LiveKit/mediasoup), клиентский код меняется только в `features/live/host.ts` и `viewer.ts`.

**Премьеры.** Это видео с `posts.premiere_at`: до начала сервер отдаёт публикацию без ссылки на файл (кроме автора), поэтому раньше времени видео не посмотреть. Во время премьеры позиция плеера = сейчас − начало, отставших плеер предлагает вернуть «к общему показу». Напоминания рассылает фоновая задача раз в 30 секунд. Чаты эфиров и премьер — комнаты `stream:<id>` и `premiere:<id>` с историей в `live_chat`.

**Звуки.** Короткие сигналы синтезируются WebAudio (`shared/lib/sounds.ts`) — без аудиофайлов; учитывают громкость, тихие часы и системные уведомления при скрытой вкладке.

**Мобильность.** Брейкпоинты: телефон (< 768 px) — нижние вкладки и шторка; планшет — рельс + выезжающее дерево; десктоп — рельс + дерево + контент (+ инфо-панель чата на широких экранах). Учитываются `safe-area`, `100dvh`, шрифт ≥ 16 px в полях ввода на iOS, длинное нажатие вместо правого клика. Service Worker кэширует только оболочку приложения и статику — личные данные API в общий кэш не попадают.

**Приложения для компьютера.** `desktop-app/` — Electron-оболочка, которая открывает сайт в отдельном окне (уведомления, звонки, демонстрация экрана). `.github/workflows/desktop.yml` собирает установщики для Windows, macOS и Linux и выкладывает их в GitHub Releases; страница «Скачать» ссылается на `releases/latest/download/<файл>`.

## Как масштабировать дальше

| Узкое место | Решение, под которое уже готова архитектура |
| --- | --- |
| Одна SQLite | Перенести SQL репозиториев на PostgreSQL: слой `Db` изолирован, запросы стандартные; FTS5 → `tsvector` |
| Один процесс WebSocket | Реализовать `RealtimeHub.sendToUser/sendToUsers` поверх Redis Pub/Sub или NATS — клиент не меняется |
| Файлы на диске | Подменить `MediaService.store/filePath` на S3-совместимое хранилище; ссылки уже подписанные и истекающие — подходят для CDN |
| Ранжирование ленты | Вынести `SCORE_SQL` в отдельный сервис рекомендаций с сигналами просмотров |
| Тяжёлые фоновые задачи | Очередь (BullMQ/NATS JetStream) для транскодирования видео, превью, рассылки push |
